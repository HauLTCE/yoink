# yoink

Sometimes you need one function or class from a large repository without adding the whole package to your dependencies. Copying the file by hand usually means chasing down private helpers in the same module, relative imports two directories up, and third-party packages whose import names do not match their package manager names.

`yoink` pulls a target symbol and the internal files it depends on out of a local directory or Git repository.

```bash
# Check what FastAPI's jsonable_encoder depends on without writing files
yoink analyze jsonable_encoder --repo /usr/lib/python3/dist-packages/fastapi

# Extract Rich's decimal filesize formatter into a single 66-line file
yoink extract /usr/lib/python3/dist-packages/rich --grab decimal --flat --out ./vendor/rich_decimal.py --force

# Extract Requests' HTTP Link header parser into a single 40-line file
yoink extract /usr/lib/python3/dist-packages/requests --grab parse_header_links --flat --out ./vendor/requests_links.py --force
```

## Output modes

`yoink` writes output in one of two layouts.

The default is `--bundle`, which keeps the source repository's relative directory structure for the files your symbol touches. If `src/billing/invoice.py` calls a function in `src/internal/tax.py`, `yoink` copies those two files into your output directory, creates empty `__init__.py` files for any intermediate Python directories that need them, copies the root `LICENSE` file if one exists, and writes `yoink.manifest.json`. Other files in `src/billing/` and `src/internal/` are ignored.

Passing `--flat` writes everything into a single source file. Modules are ordered topologically so dependencies appear before the code that calls them. Internal imports between the inlined files are removed, and standard library or third-party imports are deduplicated at the top of the file. For Python projects, `--flat` also slices each file's AST so unrelated functions, classes, and unused imports in the same module are omitted. For C and C++, `--flat` strips `#pragma once` and local `#include "..."` lines that were already inlined, placing headers before implementation files.

Add `--zip` to either mode to pack the output directory into a `.zip` archive.

## Real flat output examples

### Example 1: `parse_header_links` from `psf/requests` (40 lines from a 1,000+ line module)

`requests/utils.py` is over 1,000 lines long and imports 15 internal and standard library modules. Running `yoink extract /usr/lib/python3/dist-packages/requests --grab parse_header_links --flat --out ./vendor/requests_links.py` slices out `parse_header_links` and the one standard library module it actually uses (`re`):

```python
# Generated by yoink (flat mode)

import re

# --- module: requests.utils ---
def parse_header_links(value):
    """Return a list of parsed link headers proxies.

    i.e. Link: <http:/.../front.jpeg>; rel=front; type="image/jpeg",<http://.../back.jpeg>; rel=back;type="image/jpeg"

    :rtype: list
    """

    links = []

    replace_chars = " '\""

    value = value.strip(replace_chars)
    if not value:
        return links

    for val in re.split(", *<", value):
        try:
            url, params = val.split(";", 1)
        except ValueError:
            url, params = val, ""

        link = {"url": url.strip("<> '\"")}

        for param in params.split(";"):
            try:
                key, value = param.split("=")
            except ValueError:
                break

            link[key.strip(replace_chars)] = value.strip(replace_chars)

        links.append(link)

    return links
```

### Example 2: `decimal` from `Textualize/rich` (66 lines with private helper closure)

In `rich/filesize.py`, `decimal()` delegates to a private helper `_to_str()` in the same file. Running `yoink extract /usr/lib/python3/dist-packages/rich --grab decimal --flat --out ./vendor/rich_decimal.py` traces the intra-module AST reference, keeps `_to_str` and `decimal`, and drops unrelated functions in `rich/filesize.py`:

```python
# Generated by yoink (flat mode)

from typing import Iterable, List, Optional, Tuple

# --- module: rich.filesize ---
def _to_str(
    size: int,
    suffixes: Iterable[str],
    base: int,
    *,
    precision: Optional[int] = 1,
    separator: Optional[str] = " ",
) -> str:
    if size == 1:
        return "1 byte"
    elif size < base:
        return "{:,} bytes".format(size)

    for i, suffix in enumerate(suffixes, 2):  # noqa: B007
        unit = base**i
        if size < unit:
            break
    return "{:,.{precision}f}{separator}{}".format(
        (base * size / unit),
        suffix,
        precision=precision,
        separator=separator,
    )

def decimal(
    size: int,
    *,
    precision: Optional[int] = 1,
    separator: Optional[str] = " ",
) -> str:
    return _to_str(
        size,
        ("kB", "MB", "GB", "TB", "PB", "EB", "ZB", "YB"),
        1000,
        precision=precision,
        separator=separator,
    )
```

## Third-party dependencies

Knowing which internal files to copy is only part of getting extracted code to run. If a Python file runs `from PIL import Image` or `import yaml`, or a TypeScript file imports `@/models`, you also need to know which external packages to install and which imports are just local path aliases.

`yoink` reads the upstream project's manifest files (`pyproject.toml`, `requirements.txt`, `package.json`, `tsconfig.json`, `go.mod`, `Cargo.toml`, `pom.xml`, `build.gradle`, `build.gradle.kts`, `composer.json`, `Gemfile`, `pubspec.yaml`, `Package.swift`, `build.sbt`, `mix.exs`, and `.csproj`) to classify every import into one of three buckets:

1. Internal modules, which get pulled into the extraction closure.
2. Standard library modules (`math`, `node:crypto`, `net/http`, `std::collections`, `Foundation`, `dart:async`), which are listed in the manifest so you know the runtime surface.
3. External packages, matched back to the version constraint declared in the upstream manifest.

For Python, `yoink` maps common import names back to their PyPI distribution names (`PIL` to `Pillow`, `cv2` to `opencv-python`, `sklearn` to `scikit-learn`, `yaml` to `PyYAML`, `bs4` to `beautifulsoup4`, `dotenv` to `python-dotenv`, `jwt` to `PyJWT`, `attr` to `attrs`, `Crypto` to `pycryptodome`, `git` to `GitPython`, and `fitz` to `PyMuPDF`). For Rust, hyphenated crate names in `Cargo.toml` are matched against underscored crate identifiers in `use` statements.

## Supported languages

`yoink` supports 15 languages. It strips single-line and block comments before scanning imports so commented-out code and URLs inside string literals do not create false dependencies.

In several languages (Go, Java, Kotlin, Scala, C#, and Swift), files in the same package, namespace, or target can call each other's functions and types without an explicit `import` statement. In C and C++, a file that includes `vec3.hpp` also needs the method definitions in `vec3.cpp`. `yoink` indexes top-level definitions across the repository and links sibling files in the same package or header-implementation pair when their symbols are referenced.

## Licenses, dynamic imports, and verification

Before extracting anything, `yoink` checks top-level `LICENSE`, `LICENCE`, and `COPYING` files and classifies them (`MIT`, `Apache-2.0`, `BSD-3-Clause`, `BSD-2-Clause`, `MPL-2.0`, `Unlicense`, `LGPL-2.1`, `GPL-2.0`, `GPL-3.0`). If the source repository uses a `GPL`, `LGPL`, or `AGPL` license, `yoink` stops with a `SafetyError` unless you pass `--allow-gpl` (or `allow_gpl=True` in Python). When extraction runs, the upstream license file is copied into the output directory and its SPDX identifier is recorded in `yoink.manifest.json`.

Runtime dynamic imports such as `importlib.import_module(variable)` or broken relative imports cannot be resolved statically. `yoink` records each one under `unresolved` in `yoink.manifest.json` with its file name and line number. If you want `yoink` to fail in CI when an unresolved reference is present, pass `--strict` (exits with code `2`).

To test whether the extracted code compiles or passes a check, pass `--test "<command>"`. `yoink` copies the emitted output into a temporary sandbox directory, runs your command there, records the exit status and output in `yoink.manifest.json`, and deletes the sandbox.

## Installation and CLI usage

`yoink` requires Python 3.11 or newer. The extraction engine uses only the Python standard library; installing `typer` and `rich` enables rich terminal tables and shell completion.

```bash
git clone https://github.com/HauLTCE/yoink.git
cd yoink
pip install -e ".[dev]"
```

## Python API

```python
from yoink import analyze, extract

closure = analyze("jsonable_encoder", repo="/usr/lib/python3/dist-packages/fastapi")
print("Internal modules:", closure.modules)
print("Stdlib:", closure.stdlib)
for dep in closure.external:
    print(f"{dep.name} ({dep.version}) from {dep.evidence}")

manifest, emit_result, verify_result = extract(
    "jsonable_encoder",
    repo="/usr/lib/python3/dist-packages/fastapi",
    out="./vendor/fastapi_encoder.py",
    mode="flat",
)
print("Files:", emit_result.files)
print("Lines:", manifest.output.lines)
```

## Configuration

Place an optional `yoink.toml` at the root of your repository to set default flags:

```toml
[extract]
granularity = "file"   # "file" or "symbol"
external = "list"      # record external deps in yoink.manifest.json
max_depth = 12         # maximum BFS import depth

[safety]
execute = "ask"        # "ask", "always", or "never" for --test commands

[output]
dir = "./yoink_out"    # default output directory when --out is omitted
```
